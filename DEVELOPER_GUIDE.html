Local Setup

1
Install XAMPP. Put the project in /xamppfiles/htdocs/payroll (macOS) or C:\xampp\htdocs\payroll (Windows).
2
Start Apache and MySQL from the XAMPP control panel.
3
Open phpMyAdmin, create a database named payroll, and import the schema (see Database Setup).
4
Confirm credentials in db_connect.php (default XAMPP: user root, empty password).
5
Run composer install in the project root (PhpSpreadsheet lives in vendor/).
6
Visit http://localhost/payroll. Clean URLs require mod_rewrite (the bundled .htaccess handles routing).

Request Lifecycle

Page render (GET)

Browser  ──/payroll/employee──►  .htaccess rewrite ──►  index.php?page=employee
index.php:  db_connect.php  →  header.php  →  navbar.php  →  include 'employee.php'  →  footer + page JS

Data change (AJAX)

page JS (jQuery $.ajax) ──POST ?action=save_employee──►  ajax.php
ajax.php:  new Action()  →  $crud->save_employee()  →  echo result (text or JSON)
page JS:  toastr/Swal feedback  →  location.reload()

Two entry points only: index.php renders pages, ajax.php handles every data operation. There are no other endpoints.

db_connect.php

Creates the global $conn mysqli handle used everywhere. It also return $conn; at the end, so a double-include is harmless.

$conn = new mysqli('localhost','root','','payroll');
if ($conn->connect_error) die('Connection failed: '.$conn->connect_error);
$conn->set_charset('utf8mb4');
return $conn;
Where it comes from: index.php includes it once at the top, so any page rendered through the router already has $conn. admin_class.php includes it in its constructor for AJAX calls. Content-only page files should NOT re-include it.
SQL safety: the codebase mixes prepared statements and string-interpolated queries. For any new query that takes user input, use $conn->real_escape_string() or prepared statements. Never concatenate raw $_POST into SQL.

index.php — the router

Single layout file. After auth + header + navbar, it maps the page query param to a PHP file via a whitelist array, then includes it. Unknown pages fall back to home.

$routes = [
  'home'=>'home', 'employee'=>'employee', 'payroll'=>'payroll',
  'dtr'=>'dtr', 'attendance'=>'attendance', 'users'=>'users',
  'branches'=>'branches', 'categories'=>'categories', 'products'=>'products',
  /* ...add your page here... */
];
$page = isset($_GET['page']) ? trim($_GET['page']) : 'home';
if (!array_key_exists($page, $routes)) $page = 'home';
include $routes[$page] . '.php';

Two more responsibilities live here:

  • getRole($n) — maps role numbers to labels (see Roles).
  • Page-specific JS — at the bottom, <?php if ($page=='employee') ?><script src="assets2/js/employee.js"> blocks load only the JS that page needs.
Clean URLs come from .htaccess: ^([a-zA-Z0-9_-]+)/?$ → index.php?page=$1. So /payroll/products serves index.php?page=products. Real files (ajax.php, assets, uploads) are passed through untouched.

admin_class.php — business logic

One big class Action. Every create/update/delete/calculation is a method here. The constructor opens the DB and an output buffer; the destructor closes them.

class Action {
  private $db;
  function __construct(){ ob_start(); include 'db_connect.php'; $this->db = $conn; }
  function __destruct(){ $this->db->close(); ob_end_flush(); }

  function save_employee(){
    extract($_POST);                         // $name, $id, ...
    $name = $this->db->real_escape_string($name);
    if (empty($id)) $this->db->query("INSERT INTO employee SET name='$name'");
    else            $this->db->query("UPDATE employee SET name='$name' WHERE id=".intval($id));
    return 1;                                // echoed back by ajax.php
  }
}

Return conventions

  • Simple methods return 1 on success or an error string on failure → echoed as plain text.
  • Newer methods return an array ['result'=>true,'message'=>'...'] → ajax.php wraps it with json_encode().
  • Strict DB errors are enabled in some methods with mysqli_report(MYSQLI_REPORT_ERROR|MYSQLI_REPORT_STRICT) + try/catch.

ajax.php — the dispatcher

Maps ?action=name to $crud->name(). Mobile actions run first (before the login guard) because they authenticate with a token; the browser/admin actions sit below a session check.

$action = $_GET['action'];
include 'admin_class.php';
$crud = new Action();

// ── mobile (token-auth, returns JSON, return early) ──
if ($action == 'mobile-login-check'){ echo json_encode($crud->loginMobile()); return; }
if ($action == 'mobile-pos-save-sale'){ echo json_encode($crud->mobile_pos_save_sale()); return; }

// ── session guard for everything below ──
if (!isset($_SESSION['is_login'])){ http_response_code(403); exit('Forbidden'); }

if ($action == 'save_employee'){ $save=$crud->save_employee(); if($save) echo $save; }
if ($action == 'add_pos_branch'){ echo $crud->add_pos_branch(); }
// ...one if-block per action...
Gotcha: a missing if ($action == ...) block means the request returns an empty body and the JS reports a generic error. If a new AJAX call “does nothing”, check that its dispatch line exists here.

Form Validation — Parsley.js

Validation is declarative on the HTML, then triggered in JS before sending the AJAX. Reference implementation: component/add_user_form.php + assets2/js/user.js.

1. Markup — novalidate + per-field rules & messages

<form id="form-add" novalidate>
  <input name="name" required
         data-parsley-required-message="Name is required.">
  <select name="role" class="select2" required
          data-parsley-required-message="Please select role.">...</select>
</form>

2. JS — validate, then submit

$('#form-add').on('submit', function(e){
  e.preventDefault();
  var form = $(this);
  form.parsley().validate();
  if (!form.parsley().isValid()) return;        // blocked: messages show inline

  $.ajax({ url:'ajax.php?action=save_user', method:'POST',
    data: form.serialize(),
    success(resp){ /* toastr / Swal, then location.reload() */ }
  });
});
File uploads: swap form.serialize() for new FormData(form[0]) and add processData:false, contentType:false (see assets2/js/products.js).

UI Conventions

  • Tables: give them id="data-table" and init DataTables. Never put a colspan “no records” row inside a DataTable — it breaks cell indexing. Leave the tbody empty and let DataTables show its own message.
  • Add/Edit in one modal: a hidden <input name="id"> distinguishes update from insert. The Edit button copies row data into the modal via data-* attributes.
  • No hard deletes in newer modules: records carry a status (1=active, 0=inactive). “Delete” sets status to 0.
  • Feedback: toastr for lightweight saves; Swal for confirmations and blocking success/error.
  • After a successful save: location.reload() (the app is server-rendered).
  • Brand color: POS & newer pages use teal #219688 (dark #176358, light bg #e6f5f3). The legacy payroll spreadsheet view keeps Excel green.

Recipe: Add a New Page

1
Create myreport.php in the root. Start directly with the content (a <style> block + <div class="main-content">) — no <html>/db_connect; the router provides the layout and $conn. Model it on users.php.
2
Register the route in index.php: add 'myreport'=>'myreport', to the $routes array.
3
Add a menu link in includes/navbar.php: <a href="myreport" class="nav-link <?= $page==='myreport'?'active':'' ?>">. Gate it by $login_role if needed.
4
If it needs JS, create assets2/js/myreport.js and add a conditional <script> at the bottom of index.php.

Recipe: Add an AJAX Action

1
Add a method to admin_class.php: function save_myreport(){ extract($_POST); ...escape...; $this->db->query(...); return 1; }
2
Add the dispatch in ajax.php: if ($action=='save_myreport'){ echo $crud->save_myreport(); }
3
Call it from JS: $.ajax({url:'ajax.php?action=save_myreport',method:'POST',data:form.serialize()}).
Forget step 2 and the call silently returns nothing. This is the #1 “why isn’t it saving” cause.

Recipe: File Uploads

Form needs enctype="multipart/form-data"; JS sends FormData; the method moves the file and stores the filename.

$ext   = pathinfo($_FILES['image']['name'], PATHINFO_EXTENSION);
$fname = 'prod_'.uniqid().'_'.time().'.'.strtolower($ext);
move_uploaded_file($_FILES['image']['tmp_name'], 'uploads/products/'.$fname);
// save $fname in the DB; render with  uploads/products/<file>

Validate the MIME type (mime_content_type()) and keep only the filename in the DB.

Role is an integer on users.role, labeled by getRole() in index.php. The navbar and pages gate features on $login_role.

“Site” vs “Branch”: Timekeeping/payroll data is keyed on the sites table (site_id FKs in DTR/payroll/attendance). The POS module uses the newer branches table. In the UI, “Site” labels were renamed to “Branch” — but the underlying timekeeping data still stores site_id.

Database Setup

Core payroll tables come from your existing schema dump. The POS / cashier additions are run once on the payroll DB:

  • SQL_POS_SETUP.sql — branches, product_categories, products, pos_audit_log
  • SQL_POS_SALES.sql — pos_sales, pos_sale_items
  • ALTER TABLE products ADD COLUMN image VARCHAR(255) NULL; (if not already in the create)
  • ALTER TABLE users ADD COLUMN branch_id INT NULL AFTER site_id;
Use CREATE TABLE IF NOT EXISTS so re-running is safe. The full one-shot script was provided in the project notes.
